# Remaining launch prerequisites

This is a working demo foundation, **not the complete paid product requested**. The following are concrete blockers; none are hidden by mock success.

1. **Official documentation access:** the egress proxy denies Next.js, Replicate model pages and Paddle country-support pages. Add their official domains in cloud environment settings; configuration draft contains additions when saving succeeds. Repeat exact model/pricing/terms/retention/geography research. GitHub-hosted official SDK sources were accessible and used for integration structure only.
2. **Zambia merchant onboarding and payout eligibility:** obtain current official confirmation that a provider accepts a Zambia-based merchant selling this AI service, can pay out to the actual Zambian business/bank, and approves the business category. Paddle is a sandbox candidate only. Do not treat international customer payments or a Zambia country dropdown as merchant approval. If declined, evaluate an eligible gateway using official merchant documentation before implementing its live mode.
3. **Gateway sandbox account:** configure approved hosted checkout, four one-time USD prices and signed webhooks securely, then run real sandbox fulfillment/refund/dispute tests. The optional Paddle adapter is compiled but uncredentialed; observed flows used the local simulator. There is no live checkout mode.
4. **AI provider access and model-specific implementation:** after documented commercial/geographic approval, add credentials securely, fund the provider yourself, and approve a small billable smoke test. Complete request mapping, private temporary-output copying, moderation and worker reconciliation for a small verified launch set. Current candidates have no verified capability or cost table and remain unavailable. No model API funds were spent.
5. **Authentication and durable storage:** configure Clerk and a private S3-compatible bucket, test verified signup/recovery/sign-out, private uploads/downloads and deletion. Clerk/S3 code paths are present, not externally verified. Demo authentication is a private temporary cookie session, not a production account.
6. **Public business and policy details:** supply actual support/abuse contact, operator/legal identity and required merchant details. Have the draft terms, privacy/refund policy, consumer rights, financial retention and content moderation process reviewed for your jurisdiction and provider contracts.
7. **Deployment account:** choose a host with persistent web/worker containers, managed PostgreSQL, HTTPS and private object storage. No domain or hosting account is connected. Build/deployment instructions are supplied, but no site was published or public URL checked.
8. **Production operations:** complete live cost measurement and measured margin reconciliation, provider hard spend caps, queue-reconciliation tooling, monitored cleanup/backups, verified real gateway price/tax totals and an authenticated support workflow. Audit security controls against the chosen Clerk/storage/payment/provider configuration before accepting money.
